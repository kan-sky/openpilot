## Runtime changes

- Accept only the complete pinned N16 contract, not an arbitrary stateful graph.
- Pack the `256 x 256` map as float32 pixel values 0..255, plus the 47-value
  navigation vector. Missing optional inputs are cleared each frame. A malformed
  supplied value clears its destination and raises: the existing model fallback
  and invalid-output hold apply, rather than silently accepting that frame.
- Preserve five graph-owned recurrent states. Validate names, exact shapes,
  types and finite values; clear all states on reset or invalid feedback.
- Promote only the proven byte-image queue dataflow to FP16 for TensorRT.
  The map, navigation and model weights are not retyped by this patch.
- Reuse host output staging for subsequent state inputs, while keeping GPU
  input/output buffers distinct and maintaining stream read/write order.
- Require the explicit `stateful_v2` HELLO capability for N16 on uncompressed
  protocol 2. Do not infer support from protocol version alone.
- Retain the comma's existing invalid-output, fault hold and fallback behavior.

## Native results

The downloaded ONNX was checked against both the complete SHA256 and byte size.
The original current symlink and production cache selection were checked again
after restoration.

| Test | Result |
| --- | --- |
| Build with production engine resident and a 5 GiB test limit | TensorRT CUDA allocation failure; not proof that NX cannot run N16 |
| Exclusive build, then load in the same process | A 794981228-byte engine was generated, but deserialization failed allocating 760265088 GPU bytes |
| Fresh process, cached engine, production GPU services paused | 600/600 valid synthetic iterations; mean 26.0616 ms, p95 26.1668 ms, max 27.6528 ms |
| Recurrent reset in that native run | Exact first-output replay, maximum absolute difference 0 |
| Empty cache, separate build process, default workspace policy | CUDA allocation failure during build; process separation alone did not solve first-install reliability |
| Empty cache, isolated builder capped at 512 MiB workspace | Completed with builder exit 1: repeated GPU allocation failures, finally 760265088 bytes; TensorRT returned no engine and inference never started |
| Actual comma IPC -> USB bulk -> Jetson TensorRT | 600/600 valid replies with matching frame IDs; mean 41.4692 ms, p95 45.8549 ms, max 57.5487 ms |
| USB iterations above 50 ms | 4/600; this is not a strict 20 Hz qualification |
| USB reset replay | Exact first-output replay, maximum absolute difference 0 |

Both native tests exercised absent navigation, synthetic map/TBT, then absent
navigation again. These are not real camera frames or a real navigation route.
The USB test used the actual bulk endpoints and local IPC, not TCP over NCM.
The existing 512 KiB split-write policy was unchanged. No framing failure was
observed during the 600-frame measurement; long-duration/reconnect qualification
is still separate.

The four USB deadline overruns were frames 271, 276, 319 and 573. Their server
total times stayed about 25.7 ms, so the excess was outside the reported server
compute interval. This does not isolate USB transfer, comma scheduling or local
IPC as the cause. The comma remained in its ordinary offroad CPU policy.

The different same-process versus fresh-process results support a build/load
peak-memory or process-lifetime allocation problem. They do not prove a leak
or identify a particular TensorRT allocation owner. No model precision reduction,
power-mode change, or system memory-policy change was used.

The N16 benchmark now executes the existing build-only command in a bounded
child and waits for its exit before loading TensorRT in the parent. It validates
the full prepared spec and forbids an in-process rebuild. Production runtime
build policy is deliberately unchanged. The empty-cache failure above means
this tooling change is not by itself a validated first-install fix.
The 512 MiB cap was only an isolated diagnostic override, not a production
setting. Do not ship it as a proven solution or attribute these allocation
failures to power, hardware capacity alone, or a specific allocator defect.

## Software checks

The final focused desktop run passed 468 tests, with 14 skips. Thirteen skips
require native `msgq.ipc_pyx`; the other requires an external reference checkout.
The ONNX reference-evaluator image-queue equivalence tests ran without skips,
using ONNX 1.23.0, the version installed on the Jetson.

Coverage includes malformed specs, reset and invalid recurrent outputs,
protocol-2 capability negotiation/reconnection, protocol-3 regressions, legacy
Cinque packing, optional-input zeroing, fallback interfaces, experimental
navigation freshness and isolated build/cache failure handling. These are not
the full vehicle safety suite.

## Temporary execution and restoration

The comma was freshly checked for `IsOffroad`, `deviceState.started == false`,
Panda `noOutput`, ignition false, controls disallowed, and no running modeld,
controlsd or selfdrived. Jetson test units had bounded runtime, an updater lock,
separate cache and an independent service-restoration command.

The bulk test temporarily paused the comma manager and gracefully closed its
USB owner before starting a separate candidate. The installed power-watchdog
timeout was verified as one hour; the successful comma test unit ran 53.5 seconds.
An independent systemd stop hook resumed the manager. Other manager children
continued running. No persistent process configuration was modified.

Initial harness failures were kept separate from inference failures:

- The isolated comma package initially omitted the unchanged Cinque JSON needed
  to import contracts.
- A temporary systemd unit needed the original realtime scheduling allowance.
- A candidate control-socket path was absent after stopping the original service;
  the successful run used an existing experiment directory and the base server
  entrypoint without updater hooks.

After the test, delayed DHCP cleanup left the original USB daemon in its
intentional blocked state. The owned DHCP process was verified gone and the
offroad state rechecked before restarting only that daemon. No ownership check
was bypassed. Production `ready / Cinque v2` was subsequently confirmed.

Final fresh checks after the last builder failure confirmed `jetSON READY`,
fresh healthy USB telemetry, unchanged Cinque selection, and both production
Jetson inference/HUD services active. The original comma manager was running,
all driving processes remained off, and the offroad/Panda `noOutput` guard
passed. No experiment process remained and the temporary resume timer was
inactive. The HUD service being active is not physical panel validation:
telemetry reported no connected HUD.

Private evidence is under `.analysis/n16-jetson-20261021/`, including the original
failure logs, fresh native report, complete USB per-frame timing report and
both final empty-cache builder logs. The 512 MiB run exited on its own with
failure; it was not manually interrupted. Its restoration wrapper exited
successfully, so systemd unit success must not be read as builder success.
The experiment has no published vehicle recording or credentials.

## Navigation is deliberately not activated

The experimental `navigation/map_client.py` consumer is not wired into modeld.
It is not enough to add the upstream `carrotRouteId` schema field and start
mapsd: current upstream TBT publication can refresh the receipt time of stale
instructions, or associate old instructions with a new route.

Before activation, require shared source/route generation and the original
instruction observation timestamp, with cancellation/expiry tests. Receipt time
alone must not authorize navigation-conditioned model input.

The remaining producer integration includes the scoped upstream map renderer,
native rasterizer, route source/identity, position freshness and matching cereal
changes. It must preserve the user's Navdy/network selection. Do not merge the
entire upstream CarrotMan/vehicle GPS/control code merely to obtain mapsd.

## Independent re-verification

See [the follow-up audit](n16_reverification_20261021.md) for another native
1,200-frame N16 run, an installed Cinque USB test, wider custom-feature tests,
an optional-input validation correction, and the confirmed older Jetson HUD
package. The old host lacks the custom ambient renderer and phone-media reader;
an active HUD service alone did not establish feature parity.

## Remaining release gates

1. Source-safe real route/map/TBT producer and native rasterizer validation.
2. Build/load process separation in the production installer/runtime, not only
   a successful cached engine on this test unit.
3. Atomic, rollback-capable custom host package preserving Navdy/HUD/support.
4. Full camera/warp/modeld tests, disconnect/fallback tests, cold boot and longer
   timing/memory observations with actual DM and other workloads.
5. Separate supervised physical vehicle validation; bench output alone does not
   establish navigation behavior or safe driving.
